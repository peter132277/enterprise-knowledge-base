# 企业知识库工作规则

## 唯一入口与范围

- 使用已安装的 `enterprise-knowledge-base` Skill 处理本项目的查询、收录、媒体、健康检查、同步和飞书发布。
- 当前目录必须同时是 Codex 项目根目录和知识 Vault 根目录，并由 `.kb/config/project-binding.json` 以 `same-root` 绑定。
- 查询固定覆盖当前 Vault 中的个人与企业知识，不提供个人／企业查询模式；不得检索其他项目、其他 Vault、互联网或未同步的飞书内容。
- Codex 直接读写 Markdown 和附件。Obsidian 只用于人工浏览与编辑，不是运行时依赖。

## 本地与个人知识边界

- 普通收录只写当前 Vault，不登录或访问飞书。
- 管理员和普通员工的个人知识一律纯本地；`scope: personal` 必须保持 `publish_to_feishu: false`。
- 个人笔记、附件、图片、音视频和原件不得进入发布队列、Drive、Wiki、企业镜像、映射或公司同步状态。
- 企业共享镜像只来自已验证的飞书企业空间，并永久排除再次发布以防循环创建。

## 飞书写入确认

- 只有明确的企业内容可进入发布预览；只有 `确认批量发布` 才授权最近一次不可变批次。
- 妙记上传、Wiki 发布、成员／权限变更、删除、公开和跨空间操作必须分别预览并分别确认。
- 发布后必须回读验证；空间、成员、映射、revision、权限、正文或来源证据不一致时失败关闭。
- 普通员工只能是知识空间成员，不能成为空间管理员；应用安装、配置导入和 OAuth 不等于空间权限。

## 受管状态

- 原件放在 `10_来源`，知识放在 `20_知识`，导航放在 `30_导航`，归档放在 `90_归档`。
- 只通过受管脚本写入 `.kb` 的配置、映射、状态、日志和临时文件；不得手工伪造凭证或回读结果。
- 不输出或写入 App Secret、Token、Cookie、密码或登录凭证。
- 不覆盖未知用户修改；发现路径越界、同名冲突、本地镜像手改或远端人工修改时失败关闭。
