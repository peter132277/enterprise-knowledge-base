# 企业知识库工作规则

## 唯一入口

- 使用已安装的 `enterprise-knowledge-base` Skill 处理本项目的知识问答、附件、收录、整理、媒体转录、健康检查和飞书发布。
- 本目录必须同时是当前 Codex 项目根目录和 Obsidian Vault 根目录，并由 `.kb/config/project-binding.json` 绑定；它是唯一允许的本地知识范围。知识问答不得检索其他项目、Vault、互联网或飞书。
- 用户只发送附件也代表立即收录；音视频进入媒体路由，其他文件进入本地收录。

## 本地与远端边界

- 普通收录只写当前 Vault，不登录或访问飞书。
- 飞书妙记上传必须单独预览和确认。
- 妙记阶段的授权不授权 Wiki 发布。
- 只有 `确认批量发布` 才授权最近一次不可变批次。
- 删除、权限变更、公开、跨空间操作和新的远端写入必须分别确认。
- 企业知识库只面向管理员明确授权范围内的公司内部员工；应用安装、配置导入和员工 OAuth 都不等于获得知识空间权限。
- 空间成员权限与 Skill 的查询、收录、发布策略是两层授权。普通员工只能是空间成员，不能成为空间管理员或提高发布策略。
- 外部分享保持关闭。成员变更必须先给出可读预览并单独确认，写后回读不一致时失败关闭。

## 数据布局

- 原始证据保存在 `10_来源`。
- 可复用知识保存在 `20_知识`。
- 导航保存在 `30_导航`。
- 归档目录为 `90_归档`。
- 系统配置、映射、状态、日志和临时材料保存在 `.kb`。

## 安全

- 管理员和普通员工的个人知识一律纯本地；`scope: personal` 必须保持 `publish_to_feishu: false`，不得进入发布队列、飞书、员工镜像或公司同步状态。
- 全体已验证内部员工均可查询、收录并发布企业知识，但只能发布明确标记为 `scope: enterprise` 且通过审核和映射门禁的内容。
- 企业查询每个 Codex 会话最多执行一次前台增量同步；个人查询不触发同步，不运行后台轮询或常驻服务。
- 企业镜像只来自已验证飞书企业空间中的已发布内容，写入受管镜像区并永久排除再次发布。

- 使用 SHA-256 查重并保留原件，不覆盖未知用户修改。
- 个人、敏感、未审核和提取不完整内容默认不发布。
- 不输出或写入 App Secret、Token、Cookie、密码或登录凭证。
- 只通过受管脚本维护 `.kb/state` 和映射。
- 发现空间不一致、权限不足、同名冲突或远端人工修改时失败关闭。
