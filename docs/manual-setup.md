# 企业知识库安装 SOP

适用于 Windows 和 macOS。全程只需要选择图形界面按钮，不需要终端命令、绝对路径或配置文件。

## 总览

```mermaid
flowchart LR
    A["安装 Obsidian"] --> B["创建或打开 Vault"]
    B --> C["Codex 创建知识库项目"]
    C --> D["新建安装会话并拖入 Release ZIP"]
    D --> E["发送：帮我安装该 skill"]
    E --> F["安装完成后再新建会话"]
    F --> G["发送：初始化当前知识库"]
```

## 1. 安装 Obsidian

1. 打开 [Obsidian 官方下载页](https://obsidian.md/download)。
2. Windows 点击 `Windows`；macOS 点击 `macOS`。
3. 打开下载的安装程序，按系统默认选项完成安装。

> 界面示意：`Obsidian 下载页` → `Windows / macOS` → `安装完成`

企业知识库 Skill 不会代替用户下载或安装 Obsidian，也不会安装 Claudian 或其他 Obsidian 社区插件。

## 2. 创建或打开 Vault

首次使用 Obsidian：

1. 打开 Obsidian。
2. 点击 `创建新库`。
3. 输入任意易懂名称，例如 `知识库`。
4. 点击 `浏览` 选择保存位置，再点击 `创建`。

已有 Vault：点击 `打开本地库`，选择现有 Vault 根目录。

```text
Obsidian 起始页
┌──────────────────────────┐
│  创建新库                │  ← 新用户点击这里
│  打开本地库              │  ← 已有 Vault 点击这里
└──────────────────────────┘
```

记住的是“这个文件夹本身”，不是其中某个笔记文件。

## 3. 在 Codex 中创建“知识库”项目

1. 打开 Codex 桌面版。
2. 点击左上角项目菜单。
3. 点击 `创建项目`。
4. 项目文件夹选择第 2 步中的 Vault 根目录，不要选择其中某个子文件夹或笔记。
5. 将项目命名为 `知识库`，然后确认创建。

```text
Codex
┌──────────────────────────┐
│ 左上角项目菜单 ▼         │
│   └─ 创建项目            │  ← 点击
│      文件夹：Vault 根目录 │
│      名称：知识库         │
└──────────────────────────┘
```

完成标志：Codex 项目列表中出现 `知识库`，进入项目后显示的工作目录就是第 2 步的 Vault 根目录。不要只在 Finder 或资源管理器中打开该文件夹。

## 4. 在“知识库”项目的新会话中安装 Skill

> **安装会话必须创建在“知识库”项目内。不要在项目外、临时会话或其他项目中上传 ZIP。**

1. 打开仓库 [Releases](https://github.com/peter132277/enterprise-knowledge-base/releases)。
2. 展开最新版本的 `Assets`，下载 `enterprise-knowledge-base-marketplace-<版本>.zip`。
3. 返回 Codex，进入刚创建的 `知识库` 项目。
4. 在该项目中点击 `新建会话`。
5. 将下载的 ZIP 直接拖入新会话的输入框。
6. 确认输入框中已显示 ZIP 附件，然后输入并发送：

```text
帮我安装该 skill
```

7. 等待 Codex 完成安装，并确认结果只包含一个可见 Skill：`企业知识库`。

```text
知识库项目
┌──────────────────────────────┐
│ 新建会话                     │
│                              │
│ [enterprise-knowledge-...zip]│  ← 把 ZIP 拖到这里
│ 帮我安装该 skill             │  ← 与附件一起发送
└──────────────────────────────┘
```

不要手工解压 ZIP，也不要把 ZIP 内容复制进 Vault。

## 5. 初始化当前知识库

安装成功后：

1. 保持在 `知识库` 项目中。
2. 点击 `新建会话`，不要继续使用刚才上传 ZIP 的安装会话。
3. 在新会话中输入并发送：

```text
初始化当前知识库
```

Codex 会先显示只读预览，再让你选择本地、管理员或员工角色。确认后，Skill 只在当前项目中创建缺失的知识目录、`.kb` 受管状态、项目规则和同根绑定。

它不会：

- 联网或安装系统软件；
- 修改 `.obsidian`；
- 删除、移动或覆盖普通笔记与附件；
- 自动访问、同步或写入飞书；
- 要求输入 Vault 路径。

若提示 `unknown-agents`、`unrecognized-kb` 或保留路径冲突，请保留现场并让 Codex解释冲突；不要手工删除对应文件。

## 6. 验证

发送：`检查知识库健康度`。

本地模式应显示当前项目与 Vault 同根、查询可用；没有安装 `rg` 时会自动使用 Python 回退。只有以后明确启用飞书功能时，才需要 lark-cli、OAuth、空间映射和各自的远端确认。

## 7. 可选：配置飞书企业知识库

只有选择“我是飞书管理员，首次为公司部署”时才进入此步骤。完成管理员本人 OAuth 后，Codex 必须显示两个不带推荐标签的选择：

- `新建飞书知识库`
- `连接已有飞书知识库`

选择“连接已有飞书知识库”时，Codex 只读列出当前管理员可见的私有知识空间，由管理员选定一个后重新读取并验证。

选择“新建飞书知识库”时：

1. 输入知识库名称和可选说明。
2. 如果缺少权限，Codex 只请求列出和创建知识空间所需的最小用户权限，不自动扩大其他飞书权限。
3. Codex 显示名称、说明、私有可见性、关闭外部共享、当前管理员身份以及“不包含成员变更”的预览。
4. 只有回复完全一致的 `确认创建知识空间` 才会创建。
5. Codex 创建后立即回读空间，名称、说明、类型、私有可见性或外部共享任一不一致都停止配置。
6. 空间创建完成后，Codex 单独预览固定的“Obsidian企业知识库”七节点空白结构；只有回复完全一致的 `确认初始化知识库模板` 才会创建这些 Wiki 节点。模板不复制现有业务正文、测试文档、空间 ID 或节点 token。
7. 模板节点全部回读并验证层级后，成员方案才会另行预览；只有单独回复 `确认更新知识空间成员` 才能写入全公司内部员工成员。

“新建飞书知识库”创建的是 Wiki 知识空间；“初始化知识库模板”只创建七个空白结构节点；“为本公司创建企业自建应用”创建的是飞书应用。三者不是同一个操作，也不能共用确认。

成员授权始终保持知识空间私有并关闭外部分享。Codex 先尝试验证代表全公司的根部门；只有根部门不存在、不可见或不能唯一确认时，才使用具有“全部成员”范围的通讯录分页枚举，排除外部、停用、离职和未加入账号，并逐人添加普通成员。预览必须显示采用的策略、合格与排除人数、新增与移除数量；移除只作用于上次由 Skill 成功管理的成员，人工成员和管理员不会被静默删除。任何分页、身份、范围或完整回读不确定都会停止，且部分失败只能恢复同一个不可变计划。

公司同步会把已验证的远端 Docx 更新到 `20_知识/企业/共享镜像`，因此同步结果会直接进入普通“全部知识”检索。镜像文件使用飞书文档名；重名时才追加稳定短哈希，非法文件名字符会自动替换，旧版编号文件会在状态与哈希均一致时原子迁移。镜像仍带有永久禁止再发布的受管标记。

若发布因 Markdown 回读不一致失败，Codex 先执行零写入诊断并显示“仅格式差异、语义内容差异或不支持结构”。恢复预览仍写在原批次 journal 中，只有回复完全一致的 `确认恢复本次发布` 才能执行：仅格式差异直接完成本地收敛；语义差异最多覆盖原文档一次；远端证据变化、人工修改、不支持结构或写入结果未知均失败关闭，不会新建 Wiki 节点或重复上传原件。

每次首次本地收录还会在 Obsidian 笔记属性中写入带时区的 `imported_at`。重复收录或受管修复保留首次值，不用文件修改时间猜测。发布到飞书时，正文顶部显示同一个“收录时间”；飞书首次发布时间另存为 `published_at`，不会覆盖收录时间。

## 8. 升级已有知识库

从 v0.5.0 或其他已初始化版本升级时，仍使用与首次安装相同的会话隔离：

1. 在 Releases 下载 v0.7.1 ZIP。
2. 在原“知识库”项目中新建安装会话，拖入 ZIP 并发送 `帮我安装该 skill`。
3. 安装完成后另建初始化会话，发送 `初始化当前知识库`。
4. 初始化只升级当前项目的受管规则和缺失结构，不自动连接飞书、不初始化 Wiki 模板、不更新成员，也不改写普通笔记或 `.obsidian`。
5. 再发送 `检查知识库健康度`，确认项目绑定、公司镜像和发布状态正常。

旧版待发布笔记若没有 `imported_at`，新发布预览会失败关闭。请根据可信的原收录记录核对并补入带时区的 ISO 8601 时间，例如 `2026-08-05T10:30:00+08:00`；Skill 不会用文件修改时间猜测历史收录时间。已经确认的旧发布批次在恢复时仍保持原不可变 payload，不会借升级机会改写历史批次。
